# Programmatic API

`@readma/core` is the rendering engine behind the CLI. Everything the CLI
does is composed from exported, testable pieces — so you can integrate Readma
into your own tooling.

```bash
deno add jsr:@readma/core
```

## One-shot rendering

### `readme`

```ts
async function readme(
  config: ReadmaConfig,
  options?: Partial<GlobalOptions>,
): Promise<string>
```

Resolves the context and renders the full readme markdown. **No side
effects** — nothing is written to disk. This is what `--dry-run` and
`--stdout` use.

### `writeReadme`

```ts
async function writeReadme(
  config: ReadmaConfig,
  options?: Partial<GlobalOptions>,
): Promise<string>
```

Same as `readme`, plus a write of `README.md` inside the resolved folder
(the `folderPath` option, the workspace member path or the workspace root)
unless `options.dryRun` is set.

## Global options

| Option               | Type            | Description                                                |
| -------------------- | --------------- | ---------------------------------------------------------- |
| `workspaceRootPath`  | `string`        | Project root, default to the current directory              |
| `dryRun`             | `boolean`       | Skip the file write                                         |
| `folderPath`         | `string`        | Where `README.md` is written, derived when omitted          |
| `content`            | `ContentFile[]` | Pre loaded content, loaded from the content dir when omitted |

## Config pipeline

```ts
import {
  configIssues,
  loadContentDir,
  normalizeConfig,
  parseConfigText,
} from "@readma/core";

const raw = parseConfigText(await Deno.readTextFile("readma.yaml"), "yaml");
const config = normalizeConfig(raw);
const issues = configIssues(config);
if (issues.length > 0) throw new Error(issues.map((i) => i.path).join(", "));

const content = await loadContentDir("./readma");
```

- `parseConfigText(text, ext)` — parses `yaml`, `yml`, `toml` or `json`,
- `normalizeConfig(raw)` — keeps the known fields and drops the rest,
- `configIssues(config)` — returns `{ path, message }` data issues,
- `loadContentDir(dir)` — loads and parses every `.md` content file,
- `findConfigFile(root)` — discovers `readma.yaml` / `.yml` / `.toml` / `.json`.

## Context resolution

```ts
import { resolveContext } from "@readma/core";

const ctx = await resolveContext(config, { workspaceRootPath: "." }, {
  // both deps are injectable for tests
  detectBranch: () => Promise.resolve("main"),
  detectLicense: () => Promise.resolve({ id: "MIT", file: "LICENSE.txt" }),
});
```

The resolved context holds the repo url, branch, license info, code of
conduct path, badge list and issue template urls. Rendering is pure —
everything async happens once, here.

## Sections

```ts
import { assembleSections, renderSections, sectionTitleFor } from "@readma/core";
```

- `assembleSections(ctx)` — builds the ordered `SectionDef[]` from the
  content files, the generated sections and the config overrides,
- `renderSections(ctx, defs, renderSection)` — renders non empty bodies,
- `sectionTitleFor(ctx, file)` — config override > front matter > default.

## Lower level pieces

| Export                          | Purpose                                               |
| ------------------------------- | ----------------------------------------------------- |
| `Tocer`                         | Table of contents with GitHub compatible anchors      |
| `shields`, `shield`, `shieldUrl`| Builtin and custom shields.io badges                  |
| `renderShields`                 | Badge row plus reference-style links                  |
| `installSnippet`                | Package manager install block from language + registry |
| `markdownTable`                 | Minimal dependency free markdown table renderer       |
| `ghSlug`, `md`                  | GitHub anchor slug and markdown helpers               |
| `parseFrontMatter`              | Content file front matter parser                      |
| `mergeContent`, `sortContent`   | Content merging and ordering helpers                  |
| `io`, `setIo`, `resetIo`        | Injectable side effects surface for tests             |
| `ReadmaError`                   | Typed error thrown across the codebase                |

## License detection

`detectLicense(root)` scans `LICENSE.txt`, `LICENSE.md`, `LICENSE`,
`LICENCE.*` and `LICENSE-MIT`, and matches the file head against the MIT,
Apache-2.0, MPL-2.0, GPL-3.0 and BSD-3-Clause texts. `detectBranch(root)`
reads the git branch with `GITHUB_HEAD_REF` / `GITHUB_REF_NAME` env overrides.
