# Config overview

Readma is configured by a single declarative file at the workspace root (or
passed explicitly with `--config`):

| File            | Notes                                       |
| --------------- | ------------------------------------------- |
| `readma.yaml`   | recommended, comments and block scalars     |
| `readma.yml`    | same as yaml                                |
| `readma.toml`   | strict and unambiguous                      |
| `readma.json`   | zero ambiguity, machine generated friendly  |

Discovery follows this exact order; the first file present wins. The config
is **data only**: no code is executed, no module is imported, which makes it
safe to validate, cache and review.

## A minimal config

```yaml
title: My project
repo: owner/my-project
```

That is enough: the content comes from the
[content files](/docs/sections), badges are derived from the `repo` slug,
installation snippets from the detected language and registry, and the
license from the license file. Everything except `title` is optional.

## A complete config

```yaml
# Reference the schema for editor autocompletion
$schema: ./readma.schema.json
title: My project
description: A short description displayed under the title
repo: owner/my-project
language: ts
packageRegistry: jsr
author: owner
contact:
  email: owner@gmail.com
  x: owner
  linkedin: owner
links:
  doc: https://my-project.dev
  demo: https://demo.my-project.dev
images:
  logo: images/logo.png
  screenshot: images/screenshot.gif
license:
  id: MIT
  file: LICENSE.txt
issueTemplates:
  bug: bug-report.yml
  feature: feature-request.yml
badges:
  style: flat-square
  disabled:
    - issues
  custom:
    - name: Sponsor
      image: https://img.shields.io/badge/-Sponsor-purple
      link: https://sponsor.example
toc:
  title: Table of contents
  backToTop: false
content:
  dir: readma
repobeats: 1b12e7ffd13fd2d15772a30e8b0a995976150797
```

## Editor autocompletion

`readma schema` prints the JSON schema of the config. Save it next to the
config and reference it with `$schema` to get validation and completion in
your editor:

```bash
deno run -A jsr:@readma/cli schema > readma.schema.json
```

## What the CLI fills in for you

Three fields are auto-detected at generation time and do not need to appear
in the config of a workspace managed by the CLI:

- `language` and `packageRegistry` — from
  [workspace detection](/docs/workspace-detection), the detected value wins,
- `pkgName` — the root package name, used by the installation snippet,
- `license.id` and `license.file` — detected from the license file when
  omitted.

## Validation

`readma validate` checks the config data (types, enums, the `repo` slug
shape), every file the config references, and the content directory. See the
[validate reference](/docs/cli/validate).
