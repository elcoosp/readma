# Config reference

The config is a single object stored as `readma.yaml`, `readma.yml`,
`readma.toml` or `readma.json`. Only `title` is required.

## Identity

| Field         | Type     | Default | Description                                                                 |
| ------------- | -------- | ------- | --------------------------------------------------------------------------- |
| `title`       | `string` | —       | Readme title, displayed under the logo. Required.                            |
| `description` | `string` | —       | Short description displayed inside the header block.                         |
| `repo`        | `string` | —       | Github slug `owner/name`. Drives badges, repo links and raw image urls.      |
| `author`      | `string` | —       | Main author name, used by the contact section.                               |

## Links

| Field        | Type     | Default                | Description        |
| ------------ | -------- | ---------------------- | ------------------ |
| `links.repo` | `string` | derived from `repo`    | Repository url     |
| `links.doc`  | `string` | the repo url           | Documentation url  |
| `links.demo` | `string` | the doc url            | Demo url           |

The "Explore the docs" link only renders when `links.doc` is set, the
"View Demo" link only when `links.demo` is set.

## Contact

All fields are optional; the contact section is omitted when none is set.

| Field             | Type     | Rendered as                            |
| ----------------- | -------- | -------------------------------------- |
| `contact.email`   | `string` | Full email, linked with `mailto:`      |
| `contact.x`       | `string` | X handle, linked to `x.com/<handle>`   |
| `contact.linkedin`| `string` | LinkedIn username and badge            |

## Language and registry

| Field              | Type                            | Description                                      |
| ------------------ | ------------------------------- | ------------------------------------------------ |
| `language`         | `'ts' \| 'rs'`                  | Source language, drives the install snippet      |
| `packageRegistry`  | `'jsr' \| 'npm' \| 'crates.io'` | Registry, drives the install snippet             |
| `pkgName`          | `string`                        | Package name of the install snippet, auto filled by the cli |

## Images

| Field                | Type     | Description                                        |
| -------------------- | -------- | -------------------------------------------------- |
| `images.logo`        | `string` | Logo path or url, rendered in the header           |
| `images.screenshot`  | `string` | Screenshot path or url, rendered in the about section |

Paths are resolved against the repo slug as
`raw.githubusercontent.com/<repo>/HEAD/<path>`; without a repo slug they stay
relative.

## License

| Field           | Type     | Default             | Description                        |
| --------------- | -------- | ------------------- | ---------------------------------- |
| `license.id`    | `string` | detected from the file | SPDX identifier, e.g. `MIT`     |
| `license.file`  | `string` | detected            | License file path, drives the link |

The license section is omitted when no identifier is known.

## Issue templates

| Field                  | Type     | Description                                             |
| ---------------------- | -------- | ------------------------------------------------------- |
| `issueTemplates.bug`    | `string` | File name inside `.github/ISSUE_TEMPLATE`, drives the "Report Bug" link |
| `issueTemplates.feature`| `string` | Same for the "Request Feature" link                     |

When the template file exists, its `title`, `labels` and `assignees` are used
to prefill the new issue url.

## Badges

See [badges and shields](/docs/config/badges) for the full behaviour.

| Field               | Type                      | Description                       |
| ------------------- | ------------------------- | --------------------------------- |
| `badges.style`      | `'for-the-badge' \| 'social' \| 'flat' \| 'flat-square' \| 'plastic'` | Shields.io style |
| `badges.disabled`   | `string[]`                | Builtin badge ids to remove       |
| `badges.custom`     | `{name, image, link}[]`   | Badges appended after the builtin ones |

## Table of contents

| Field               | Type      | Default             | Description                            |
| ------------------- | --------- | ------------------- | -------------------------------------- |
| `toc.title`         | `string`  | `Table of contents` | Collapsible block summary              |
| `toc.hide`          | `boolean` | `false`             | Remove the table of contents           |
| `toc.backToTop`     | `boolean` | `false`             | Add a "back to top" button per section |

## Content

| Field        | Type     | Default   | Description                                              |
| ------------ | -------- | --------- | -------------------------------------------------------- |
| `content.dir`| `string` | `readma`  | Directory holding the markdown content files, per package |

## Misc

| Field        | Type     | Description                                                     |
| ------------ | -------- | --------------------------------------------------------------- |
| `coc`        | `string` | Code of conduct path, detected at `.github/CODE_OF_CONDUCT.md` by default |
| `repobeats`  | `string` | Repobeats svg hash from https://repobeats.axiom.co/configs      |
| `$schema`    | `string` | Json schema reference for editors, ignored by the engine        |

## Sections overrides

`sections` maps a section id to `{ title, hide }` overrides. Config entries
win over front matter, front matter wins over the defaults. See
[content files](/docs/sections).

```yaml
sections:
  license:
    title: Legal
  roadmap:
    hide: true
```

## Workspace internals

| Field                      | Description                                                        |
| -------------------------- | ------------------------------------------------------------------ |
| `workspaceMember`          | Set by the cli when rendering a member readme                       |
| `root.members`             | Set by the cli when rendering the workspace root readme             |

Both are managed by the cli; you rarely write them by hand.
